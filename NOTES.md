# NOTES — reference, working state & decisions

Reference for continuing work on the roll library (rolls ↔ frame grid ↔ detail view navigation), thumbnails, and the GPU detail pipeline.

## Current state

> **RAW pipeline rewrite (steps 1–8) landed** on `raw-pipeline-rewrite`: the
> film path is now **film-only and density-domain** with one pointwise
> `film::Develop` (exposure, contrast, black, white, midtone pivot) shared by
> the WGSL detail shader and the CPU bakes. The roll's clear-film base comes
> from a designated calibration frame. The editing drawer leads
> with a **histogram (Output/Input axis toggle, Output default) + classic
> `T(p)` curve overlay** (`pipeline::histogram_from_develop` +
> `ui::HistogramPlot`; `film::Develop::curve_point` is the straight diagonal at
> the identity controls, and exposure moves the bars, not the curve).
> `just check` + `cargo test --locked` are green (205 tests); the only
> outstanding item is the manual visual check on real negatives. See
> `docs/raw-pipeline-rewrite.md`.

### File layout

- `src/app.rs` — UI (tiles, detail crossfade, editing panel), state + messages, the async decode/export pumps.
- `src/pipeline.rs` — the RAW-to-image pipeline shared by every CPU bake: sensor decode (`decode_raw_detail`), mono reconstruction (`flatten_bayer`, `downsample_thumbnail`), the one density develop tail (`bake_develop` → `film::Develop::apply` + sRGB), and geometry (`crop_rgba`/`rotate_quarters`/`orient`), plus `DetailDecode`.
- `src/ui.rs` — the widget tree as pure functions of `&AppModel`: library page, frame grid, detail view, editing panel, help overlay, and the tile/card/dot widgets, plus `FrameMeta`/`load_frame_meta`.
- `src/shader.rs` — `DetailProgram` implementing `iced::widget::shader::{Program, Primitive, Pipeline}` for the detail view; the WGSL `develop()` mirrors `film::Develop` exactly (parity-tested). The bind group is texture + sampler + uniforms (no tone LUT).
- `src/edit_manifest.rs` — per-roll edit persistence: `RollManifest`/`EditData`/`ToneEdit` (serde+toml), the `.film-roll.toml` sidecar reader/writer (atomic temp+rename), `reconcile`, unit tests.
- `src/exif_writer.rs` — EXIF writing for exports: `shifted_datetime` (ISO date + seconds), the hand-rolled TIFF blob (`build_tiff`), and the JPEG APP1 splice (`jpeg_app1`/`splice_after_soi`); PNG's `eXIf` is written via the `png` crate directly. No new crates; its unit tests round-trip through `exif` (kamadak-exif).
- `src/export.rs` — the export path: `ExportPreset`/`ExportFormat`/`ExportSize`/`ExportOptions` (the dialog's `options_for_choice`/`export_format_choice`/`export_overwrite_choice`), file naming (`export_name`, `dated_export_name`, `roll_hash`, `temp_export_path`, `export_fraction`), `is_export_artifact` (keeps exports out of the frame grid), and the encoders `export_frames`/`export_one`/`export_jpeg`/`export_png`.
- `src/library.rs` — roll-list logic: ISO date helpers (`parse_iso_date`, `valid_iso_date`, `roll_dates_valid`, `format_roll_card_dates`), the date-aware search (`MonthAliases`, `parse_search_query`, `roll_matches_terms`, `filtered_rolls`, `roll_date_cmp`), the unified grid cells + arrow-key nav (`LibraryCell`, `library_cells`, `library_cell_index`, `nav_target`, `paginate`), and the roll-metadata manifest setters (`record_roll_*`).
- `src/config.rs` — persisted app config (cosmic-config derive, schema v1): the roll list `rolls: Vec<String>` (absolute roll directories).
- `src/shader/exposure.wgsl` — fullscreen-triangle WGSL (three NDC vertices whose triangle clips to the viewport) that samples a linear mono `R16Float` texture and applies the pointwise density develop, mirroring `film::Develop::apply` in `develop()`: the `2^-EV` sensor gain hits the transmission first, then density `-log(value/dev_base)/log(10)` → the black/white window → pivot-power contrast, with `shade()` sRGB-encoding the result. `view_uv`/`overlay_sample`/`rotate_uv`/`rotated_dims`/`crop_box_display` map fragments through the zoom/pan + crop + quarter-turn transform, `show_mask` dimming everything outside the crop, and `view_uv` does the `ContentFit::Contain` math the shader widget can't. The bind group is texture + sampler + uniforms only. The Rust twin is pinned by `develop_matches_wgsl_transcription`.
- `src/film.rs` — the pointwise density develop (`Develop`: base-relative `density = log10(base/(transmission·2^-EV))` → black/white window → pivot-power contrast) + clear-film base measurement (`measure_base`, `MIN_PLAUSIBLE_BASE`).
- `src/detail_area.rs` — `DetailArea` widget: an iced-`MouseArea` clone that reports cursor positions relative to the widget **center** (needed by the zoom-anchor math), fires `on_release` when the cursor leaves while pressed (iced suppresses release outside bounds), and stays stateless (`tree::State::None`). A11y nodes omitted (the trait default covers it; no direct `iced_accessibility` dep).
- `src/error.rs` — `FrameError` (thiserror, `Clone` so it rides `Message` payloads): the single error type for the decode pipeline, exports, and frame-metadata reads. Replaces the old `Result<_, ()>` / `Result<_, String>` ad-hoc error surface.
- `src/logging.rs` — the `log`-facade sink: a ~70-line stderr writer installed in `main`. **Target-scoped by default**: only this crate's records are emitted (all the app's diagnostics are `log::error!`), so the dependency tree (libcosmic/iced/wgpu/zbus/i18n-embed) stays silent unless opted in — `RUST_LOG=debug` (bare) raises every scope, `RUST_LOG=negiri=trace` only ours; `EXPOSURE_TRACE_DETAIL`/`EXPOSURE_TRACE_REBAKE` force our crate to `trace`. Output keeps the established prefix-less style (`failed to decode /path: reason`).

### Current behavior

- **Library page**: the configured film rolls (config key `rolls`, a `Vec<String>` of absolute directories) are listed as cover cards in a responsive grid, **date-sorted** — undated first in name order, then dated rolls newest-start-date first (pure `roll_date_cmp`, applied at the single `library_cells` choke point shared by grid render, arrow-key navigation, and pre-select; the backing `self.rolls` order stays name-sorted). There is no library toolbar: the only header control is the search (see Search). The library **pre-selects** the first visible roll whenever nothing is selected (`select_first_visible_roll`, no-op while a roll is open) so it never idles un-highlighted; a freshly added roll skips this and drills straight into its frame grid with the selection pinned for backing out. Each card is one interactive unit (`MouseArea`: `RollSelected` on press, `RollActivated`/Enter drills in via `open_roll`): a full-bleed cover, the display name, and a caption row with the frame count plus (dated rolls) the human-readable date range. The cover is flush to the card's top edge with `content_fit(ContentFit::Cover)` + a **top-only** `border_radius(...bottom(radius))`: the pinned iced-wgpu image shader clips to a rounded-box SDF whose radius is rotated 180° from `border::Radius`'s struct order (first two entries render on the bottom), so the top clip is expressed via `.bottom()`; `radius` comes from `cosmic::theme::active().cosmic().corner_radii.radius_s[0]`, matching the COSMIC system Roundness setting exactly. **Selection is an overlay, not a card style**: the card sits in a `Stack` on a `Container::Primary` surface, and a selected card gets a transparent `Container::custom` accent ring (2.0, `radius_s`) on top, so the full-bleed cover can never hide the highlight (iced paints a container border *behind* its children); the ring is decorative (no `MouseArea`). Empty states: a truly empty library shows **no hint** (the Add Roll tile alone is self-explanatory); the `no-rolls-found` overlay survives only for the search-mismatch case.
- **Add Roll tile & remove roll**: an **Add Roll** tile (a `Container::Primary` card via the shared `selectable_tile` wrapper, same selection ring) is always the first grid cell while **no search is active** — `library_cells` prepends it purely on `query.trim().is_empty()`, so a non-blank search hides it. A single click selects it; double-click (or Enter) opens the system folder picker (`cosmic::dialog::file_chooser::open::Dialog::open_folder()` via `open_roll_picker()`/`Message::AddRoll`). Re-adding an existing roll re-scans it (the tile doubles as manual refresh); **File → Add roll** is the inline-picker alternative mid-search. `RollAdded(dir)` works from anywhere (the roll persists app-wide), pins the new roll in the library selection, and drills straight into its frame grid with the first frame pre-selected; backing out with Esc returns to the library with it highlighted. **Remove roll is non-destructive**: the library roll-drawer button / File → Remove roll (gated to the rolls view with a roll selected) drops the dir from the persisted config (`rolls.retain` + `persist_config`), clears a stale selection + closes the roll-info drawer, and never touches the files or `.film-roll.toml` — reversible via Add roll.
- **Roll metadata (name, dates, film/location/camera/lens/notes)**: the roll-info context drawer (`ContextPage::RollInfo`, the Space/Details drawer target on the library page — needs a `LibrarySelection::Roll`, never opens while a roll is open) lists the editable **name** (heading text field, commit on Enter; `None` falls back to the directory leaf; library card title + search + sort tiebreak all read it), the full path, frame count, and cover file name (or `no-cover`); then the free-form film metadata — **Film**, a divider, the **Dates** fields (start + optional end, ISO `YYYY-MM-DD`, Enter to commit; validation via `valid_iso_date`, `end ≥ start` enforced by `roll_dates_valid`), **Location**, a divider, **Camera**, **Lens**, a divider, and **Developer Notes** — every metadata field a single-line text field committed on Enter (empty clears it); then a divider and the Remove-roll button. The five metadata fields persist as flat optional manifest strings (`film`, `location`, `camera`, `lens`, `developer_notes`) surfaced as the `RollMeta` aggregate (`RollManifest::meta()`/`set_meta()`, `library::record_roll_meta`), with drawer drafts in `AppModel::roll_meta_draft` (`RollMetaField` + `RollMetaDraftChange`/`RollMetaDraftSubmit`, re-seeded by `sync_roll_drafts`). The card date caption is human-readable with localized short months (`format_roll_card_dates`; e.g. `May 30 - Jun 2 2026`), falling back to the raw ISO range on malformed input. **Calibration frame**: one designated frame per roll supplies its clear-film base — designated via **Edit → Calibrate from this frame** (`MenuAction::CalibrateBase`, enabled with a frame open) and marked by a theme-accent dot in that tile's bottom-right corner (`is_calibration_frame`/`calibration_frame_dot`); the manifest stores the designation (`calibration_frame: Option<String>`) and the measured transmission (`base: Option<f32>`).
- **Search (library-only, debounced, date-aware)**: the header search applies only to the roll library — an open roll's frame grid always shows every file, and the header search control is hidden entirely while a roll is open. The control mirrors cosmic-files' `header_end`: inactive → `system-search-symbolic` icon button (`.tooltip("Search")`, Ctrl+F also activates); active → a fixed-width (240) `search_input` that hides back to the icon once cleared. Typing is **debounced** (trailing edge): `search` is the live typed draft, `search_filter` the applied term; each keystroke bumps a monotonic `search_version` and spawns a 300 ms `SEARCH_DEBOUNCE_MS` task emitting `SearchCommitted(term, serial)`, applied only when `serial == search_version` (so a stale commit can't resurrect a clear/escape). Matching covers names **and dates**: whitespace-separated tokens are classified by `parse_search_query` into `Text` / `Date{year}` / `Date{month}` and ANDed by `roll_matches_terms` — `2026`, `may`, `May 2026`, or `chi 2026` all work; a `Date` term also matches the literal token in the roll name. Month names resolve through `MonthAliases` (localized `month-01`…`month-12` + the always-English full/3-letter set); ISO parsing is single-sourced in `parse_iso_date` (`valid_iso_date` and `format_roll_card_dates` delegate to it). Escape on the library page deactivates the search first; inside a roll it leaves the term alone (persists and reapplies on return).
- **Frame grid**: an open roll's grid lists every regular non-dot file in the roll directory as tiles, sorted by name (dotfiles — including the edit manifest or its temp — never become tiles); there is no frame search. Columns adapt to window width via `Grid::fluid(THUMB_SIZE)` + `.height(Sizing::AspectRatio(TILE_ASPECT))` inside a scrollable that wraps the grid in `widget::container(grid).width(Length::Fill).padding(space_s)` (the 16 px inset — this iced fork's `Scrollable` has no `.padding()` builder). Cells never exceed `THUMB_SIZE` px and stay square. Each tile is **image-only** (the filename caption was dropped — the name lives in the frame-info drawer): a single `MouseArea` (`FrameSelected` / `ThumbnailActivated` double-click) wraps the image + a `space_s`-padded name slot on a `Container::Primary` surface, with the same shared `selection_ring()` overlay as the library when `frame_selected` matches; `ContentFit::Contain` (never cropped, so a film frame's full framing stays visible); `image-loading-symbolic` / `image-missing-symbolic` icons for pending/failed. Opening a roll pre-selects its first visible frame (highlight/latch only — the detail view stays closed and Enter opens it).
- **Frame-info drawer**: on the grid with a highlighted frame, Space/View→Details opens `ContextPage::FrameInfo` showing the frame's name, dimensions, and basic EXIF — camera (make+model), ISO, shutter speed, aperture, focal length, lens, capture date — parsed via `kamadak-exif` on demand (`load_frame_meta`, results cached per `Tile`, `frame_meta_inflight` de-dupes) with a quiet "No metadata available" hint on unparseable files. When the roll has a start date it leads with an **Original date** row — `start_date` + the frame's full-roll position in seconds via `shifted_datetime`, i.e. exactly the `DateTimeOriginal` the export stamps on that frame (see Export).
- **Thumbnail pipeline** (`convert_thumbnail(image, max_size, develop, crop, rotation)`): `rawloader::decode_file` → `downsample_thumbnail` (one fused pass — normalize, discard masked borders, and **phase-preserve a downscale straight from the sensor samples** into a small *true sensor-linear* mono, the same domain the detail decode produces, never materializing a full-res buffer: bayer classes rescaled onto one common base per `class_gains`, cpp≥3 via luma-of-channel-means which is exact because luma is linear) → the one shared tone tail `bake_develop` (the pointwise density develop then sRGB — the same math the detail shader runs per fragment) → u8 quantize as `[v,v,v,255]` → EXIF `orient` → crop (`scale_crop` then `crop_rgba`) → rotation (`rotate_quarters`) → `Handle::from_rgba`. That ordering composes as `rotate_ccw(crop(orient(EXIF)))`, matching the detail shader, and is why grid == detail == export hold structurally. Accepted tone swap: per-class bases are measured at thumbnail scale after the downscale instead of on full-res samples (flatten-before-average), so high-contrast blocks can differ subtly from the detail render. Thumbs decode progressively, up to `MAX_CONCURRENT_THUMBS` (4) in flight at once on the blocking thread pool, in file order. Roll covers decode through the same pipeline **baking in the cover file's stored develop/crop/rotation from the roll's manifest** — so a roll tile preview mirrors the edited frame (untouched rolls stay byte-identical).
- **Mono reconstruction (noise)**: `flatten_bayer` (`src/pipeline.rs`) treats a monochrome negative as a luminance scene behind a Bayer CFA: it measures each class's clear-film base, `class_gains` rescale all classes onto one common base (neutralizing the light-table/sensor cast), and each **2×2 CFA cell is averaged post-gain into one output pixel** (edge-replicated partial cell for odd dims) — ~1.6–2× less read noise than a single-site readout, strongest at native zoom where `resize_area` is the identity. Output is half-resolution per axis; `DetailDecode::src_long_edge` stays in **sensor** pixels so crop authoring (grid bake + detail) shares one reference frame (grid == detail == export). This is a luminance reconstruction for a monochrome scene, not a demosaic; color negatives will need a real demosaic. `downsample_thumbnail` has its own fused averaging path and is unaffected.
- **Film develop & base measurement** (`src/film.rs`): `Develop { exposure_ev, base, black, white, contrast, pivot_offset }` is the single pointwise tone function, all in optical density: `density = log10(base / (transmission·2^-EV))` → `x = (density−black)/(white−black)` clamp → pivot-power contrast (`x/p)^k` / `1−(1−p)((1−x)/(1−p))^k`, identity at `k=1`). Clear film prints black, `white` prints white. Exposure is a density offset (`2^-EV` on the transmission, +EV brightens). `measure_base` (95th percentile of a clear-film patch) sets the roll base; `MIN_PLAUSIBLE_BASE` (0.1) rejects frames with no measurable margins; `DEFAULT_FILM_BASE` (0.8) / `DEFAULT_D_MAX` (2.4) are the uncalibrated fallbacks.
- **Detail view**: double-clicking a tile's image overlays a detail view for that frame on an opaque surface that hides the still-mounted thumbnail grid (the grid never leaves the widget tree, so iced preserves its scroll position across open/close). The detail surface is painted with the window background color (`theme.cosmic().background(false).base`) so the letterbox bars show the same backdrop — in crop mode it switches to white; a full-surface `MouseArea` (`Message::Ignore`) swallows pointer input over the caption/bars while the preview itself is the interactive `DetailArea`. While the GPU decode lands, the cached 384 px thumbnail is shown; once the shader is ready, the thumbnail fades OUT 1→0 over `FADE_SPEED = 5.0` (driven by a `time::every` animation subscription) so the GPU mono texture takes over without flicker (the fade was flipped from fade-IN because the GPU layer is bottom-to-top in the `Stack`). Escape closes the view and drops all detail buffers (the overview LRU survives). Only ONE critical hi-res decode is in flight; selecting another file queues behind it (stale results discarded by name). A separate tiny channel preloads neighbor overviews into the LRU so Left/Right paging is instant. Loading is progressive through that single slot: a 2048-edge overview first, and a native-cap re-decode once the zoom reaches the **level-up trigger** — the earlier of the current texture's 1:1 ("100%") cap and `NATIVE_ZOOM_THRESHOLD` (2× contain) — that replaces the texture in place (same framing, no crossfade). The cap term matters: the wheel clamps zoom at 1:1, so on a wide full-screen preview (context drawer closed) the overview's 1:1 can sit below 2.0 and a *fixed* threshold could never be crossed — the level-up would never fire (the hi-res "does not load when drawer closed + full-screen" bug); firing at the cap is exactly when the overview is at 100% and deeper zooming needs native. While that native re-decode runs the wheel keeps working: the zoom clamp rises from the overview's 1:1 to the **projected native 1:1** (`max_detail_zoom_for_wheel` — the source's own 1:1 computed via `shader.zoom_100_for` for the texture `resized_dims(src, MAX_TEXTURE_EDGE)` will produce), so you can keep zooming through the load but never past the pixels native pixels cover, and the landing re-clamp re-derives that same value exactly (no yank-back); `reclamp_detail_zoom` uses the projected cap too, so a mid-load window/drawer resize or crop edit can't snatch the zoom back to the overview's 100%. A cached overview shows the shader immediately (no thumbnail fade). A header-top-right spinner (`indeterminate_circular`, 18 px, beside the export ring) runs while any hi-res decode is in flight for the open detail view; it is gated on `selected.is_some() && detail_inflight.is_some()` because `detail_inflight` is NOT cleared when Escape closes the view (only roll-close clears it) — the `selected` term keeps a still-running decode from spinning on the grid below.
- **Zoom & pan**: the preview surface is wrapped in `DetailArea`; the wheel zooms (one notch ≈ half a `log2` unit, gated on the cursor being over the preview itself) and press+drag pans. The maximum zoom is the **1:1 ("100%") cap** — one image pixel per one physical screen pixel — computed dynamically as `1 + log2(max(dw/sc_w, dh/sc_h))` from the loaded texture (cropped + rotation-swapped) and the preview area's physical size (`DetailProgram::zoom_100`), clamped to `[1.0, max_detail_zoom()]` behind the `MAX_DETAIL_ZOOM = 7.0` absolute ceiling; the cap is re-derived + re-clamped whenever it can change (preview resize, drawer open/close, a native level-up installing a larger texture, crop/rotation edits, crop-mode padding). Zoom is **continuous from the contain fit**: `scale = contain_s · 2^(zoom−1)`, so at `zoom == 1` the view is byte-identical to `ContentFit::Contain` and bars recede gradually; the frame fills the shader at `1 + log2(cover/contain)` and keeps overflowing beyond (never clipped to the letterbox band — explicit user requirement). The pan keeps the image point under the cursor pinned across zoom steps (`zoom_about_anchor`); `DetailArea` supplies the cursor **center-relative** (iced's plain `MouseArea` gives top-left-relative positions, which would shift the anchor by the unknown widget center). Zooming back out to 1 re-centers (fit view must be centered); zooming out past cover does not snap. Pan is unclamped (bars show when dragging past an edge). `on_release` also fires on cursor-leave-while-pressed and on `CursorLeft`, so a grab-pan can never stick; wheel zoom is additionally guarded to the preview so scrolling the drawer/bars never zooms. The measured preview size (`detail_area_size`) is **view geometry, not per-frame state**: `clear_detail()` no longer drops it, because frame paging keeps `DetailArea` mounted with unchanged bounds and `DetailArea` only re-publishes on an actual size change — resetting it left the 1:1 cap disabled (fallback `MAX_DETAIL_ZOOM`) until an editing-drawer toggle forced a resize, so the wheel could zoom past native 100% before the drawer had ever been shown. The preview also advertises its pan affordance: once zoomed past the contain fit (`zoom > 1.0`, where the image overflows the preview in at least the constraining axis) `DetailArea` shows a **grab** hand, switching to a **grasping** hand while a grab-pan drag is live (its existing `.interaction()` hook, driven by `AppModel::detail_cursor_interaction` → the pure `detail_cursor_for`).
- **Tone model (persisted, orthogonal controls — exposure, contrast, black, white, midtone pivot)**: a single **film-only density path** (`docs/raw-pipeline-rewrite.md`). Every control maps straight onto `film::Develop`: **Exposure** a `2^-EV` density offset, **Contrast** a power about the midtone pivot, **Black**/**White** the density anchors the window normalizes into, **Midtone** a signed offset from the window midpoint the contrast bends around. Identity = `exposure 0`, `contrast 1`, `black 0`, `white 2.4`, `pivot 0`, which is exactly the plain normalized density. The persist layer stores exact `i16` ticks against a **frozen integer grid** (`edit_manifest::{EV_TICKS_PER_EV, TONE_TICKS_PER_UNIT}` = `100`, with `BLACK_TICKS_PER_UNIT` = `200` — black is twice as fine because the black anchor shifts the develop numerator additively and is otherwise ~2× stronger per tick than White). The tick counts are the storage contract; every control's **range, slider and key steps are derived from them** (`edit_manifest::{exposure_range, contrast_lift_range, contrast_power_range, black_range, white_range, pivot_range}`, `*_STEP`/`*_TICK`), so no UI change can reinterpret a stored value. Every control has exactly **two rungs**, both integer tick counts: a coarse step of `COARSE_TICKS = 5` ticks (a bare slider drag) and a fine step of `FINE_TICKS = 1` (Shift + drag). The bare **keys** ride the same ladder rather than carrying independent literals: `EDIT_STEP_*` is derived as `edit_manifest::*_STEP * KEY_COARSE_STEPS_*` (exposure 5 coarse steps = 0.25 EV, develop 4 = 0.20, black 4 = 0.10), so a key and a drag can never desynchronize — pinned by `bare_key_steps_are_whole_coarse_steps`, and `EDIT_NUDGE_*` is one stored tick. Because both rungs (and the key multipliers) are whole ticks, re-tuning either one can only change *which* stored values a control can reach, never what a stored count means (pinned by `coarse_and_fine_steps_are_whole_numbers_of_stored_ticks`), and a fine edit is stored with no rounding, hence no jump-back on release. A tick converts to its control's value by **dividing by that integer count** (`step_value`), which is correctly rounded — `70` ticks is exactly `f32(0.7)` — where multiplying by an f32 quantum would carry the quantum's own error; the coarse steps are consequently bit-identical to the pre-refinement `0.05`/`0.025` literals. `shift_step` only quantizes the value — the handle still follows the cursor at the same pixel slope; the win is sub-tick placement (at the drawer's track width, the coarse pivot step is ~19 px of travel vs ~4 px fine). The stored fields are `exposure_ticks`, `contrast_lift_ticks` (`+log2(power)`), `black_ticks`, `white_ticks`, `pivot_ticks`; the runtime `ToneEdit` holds the f32 values and `ToneEdit::to_develop(base)` builds the per-frame `Develop` from the roll's resolved clear-film base. `detail == export == grid` hold structurally: the GPU WGSL `develop()` and the CPU `film::Develop::apply` are the same expression, pinned by `develop_matches_wgsl_transcription` (≤1e-6) and `bake_develop_matches_the_develop_function`. **Accepted consequence**: a control's tick bounds *are* its slider range *and* its encode clamp, so **narrowing** a range would clamp a stored edit on that frame's next exposure/develop write, paste, or reset — range changes are therefore widen-only while manifests exist (widening never rewrites anything).
- **GPU exposure**: the detail view runs through an `iced::widget::shader::Shader` that uploads the linear mono `Vec<f32>` once as an `R16Float` texture at decode time (single channel, f32→half in `Primitive::prepare` via `mono_to_half_bytes`; **half-float is essential — `R32Float` is not filterable on WebGPU/wgpu 28** and would fail the bind-group validation). The WGSL `develop()` evaluates the density develop per fragment and sRGB-encodes. `ExposureChanged(f32)` / `DevelopChanged(contrast, black, white, pivot)` write uniforms via `shader.set_exposure`/`set_develop` — zero CPU re-encoding, zero per-frame `Handle`, no debounce. `Uniforms.exposure` is the `2^-EV` sensor gain; `dev_base/dev_black/dev_white/dev_contrast/dev_pivot` mirror the Rust develop. The texture is uploaded with a **full CPU-built mip chain** (`build_mip_chain`: linear-light 2×2 area-average halving, `mono_to_half_bytes` per level, `mip_level_count = chain len`) and the sampler sets `mipmap_filter: Linear`, so minified views sample pre-filtered texels instead of aliasing film grain; mips average the TRUE sensor data before the per-fragment develop, matching the CPU bake's flatten-before-average ordering, and magnification keeps LOD 0.
- **Editing panel**: with a detail view active, the editing panel is the COSMIC **context drawer** side pane (`core.window.context_is_overlay = false`, so the image shrinks to make room). It follows the detail view's **per-view remembered state** (`drawer_memory`); the user raises it with **Space** or **View → Details…** — there is no header toggle anymore. Content, top to bottom: the exposure slider (`edit_manifest::exposure_range()` = −3.00 to +4.00 EV, coarse step `EV_STEP` with Shift down to one `EV_TICK`, base +0.7 default); the **persisted** develop controls — **Contrast** (`app::contrast_lift = +log2(power)` on the `contrast_lift_range()` `-3.0..=3.0`-stop track, `contrast_power_range()` `0.125..=8.0`), **Black** (`black_range()` `-1.0..=1.0` density anchor, half the develop step), **White** (`white_range()` `0.5..=5.0`, default 2.4; the one control on an INVERTED UI axis — the density anchor darkens as it rises, so the slider shows `white_ui_from_density` and right/`.` brightens/clips highlights, matching every other control's rightward direction), and **Midtone** (`pivot_range()` `-0.5..=0.5` pivot offset) sliders; each emits `Message::DevelopChanged(contrast, black, white, pivot)` and the other values travel along so the develop stays fully defined; a divider; a `Rotation: N°` line; the conditional `Crop: T R B L` readout; then the reset row (**Reset all edits** restores every edit to the state the panel was opened with). While the GPU shader is loading the panel shows only the title. The drawer width comes from libcosmic's `context_width()` (344–480 px).
- **Crop (movable/resizable window, keyboard-driven, aspect-locked)**: the crop is a sub-rectangle of the source, **moved** and **resized** in **crop mode** only (a VIM-like modal state: bare `c` or **View → Crop mode** toggles it; while on, every non-crop edit key is inert, the image is shown over **white** with everything outside the crop **dimmed** by the shader's `overlay_sample` layer, and Esc exits crop mode first — one more press closes the view). Keys: `h`/`j`/`k`/`l` **and** the arrows move the window (`CROP_STEP_PX`=5, Shift=`CROP_NUDGE_PX`=1), `-`/`=` resize it about its center (`CROP_RESIZE_STEP_PX`=10, Shift 1 px) — move keeps size/aspect, resize scales by `s = 1 + delta/long_edge` so the aspect is preserved exactly, both clamped to `[MIN_CROP_WINDOW=4, full frame]`. Margins are stored in **source pixels** per edge as `CropMargins { top, right, bottom, left }` on `EditData` — a window is just `left=x, top=y, right=W−x−w, bottom=H−y−h`, authored in the **display-oriented source frame** (post-masked-borders, EXIF-rotated upright; keyboard trim bounds resolve the true source dims via `DetailProgram::source_dimensions()`, restored from the downscaled texture + `src_long_edge` in `DetailProgram::new`, NOT the 2048-overview dims), and interpreted *fractionally* at any texture resolution (the Rust-side `crop_uv_geometry` maps by `tex/src` per axis, and `display_source_dims`/`scale_crop` do the same for bakes — the old overview-dims reference bug that moved the stored crop's meaning between levels is fixed). Film-frame moves are **visual/rotation-aware**: `crop_move_direction(MoveDir, rotation)` cycles the direction by `rotation & 3` CCW turns, matching the shader's `rotate_uv`. Live preview is uniform-only zoom-to-fit: `view_uv` anchors the contain/zoom scale to the CROPPED frame, so trimming re-fits the kept content. **Baked everywhere** in grid/cover/export as `crop_rgba` then `rotate_quarters` (the detail shader path does NOT re-crop — it would double-crop). Commit cadence: moves are live and persist on crop-mode close / flush points (`commit_edit()`); **Reset crop** zeroes only the crop, then persists immediately.
- **Display rotation (per-frame, persisted + baked)**: `r` rotates the detail view counter-clockwise in 90° quarter-turns, composed AFTER the crop and on top of the EXIF orientation (`rotate_ccw(crop(orient(EXIF)))`; crop margins stay authored in the EXIF-upright frame). `AppModel.rotation: u8` (0–3, `& 3` clamped) is loaded per open from the manifest, applied to the shader as a **uniform-only** `rot: f32` (`rot == 0` renders byte-identical); WGSL helpers `rotate_uv`/`rotated_dims`/`crop_box_display` drive `view_uv` + the dim overlay, pinned by Rust mirror tests (`rot_uv`/`rotated_dimensions_swap_axes_for_odd_turns`). Persisted as `EditData.rotation: u8` (manifest v1); **not** part of `ToneEdit`, so copy/paste excludes it (like crop) and `set_tone` preserves it. Baked into grid tiles and roll covers via `rotate_quarters(rgba, w, h, turns)` after `crop_rgba`, so tiles match the rotated detail view.
- **Selection & clipboard**: frame selection is `selected_frames: HashSet<String>` (drives the selection ring + paste target) alongside the primary `frame_selected` focus. `apply_frame_click` is pure: plain = clear+select, Ctrl+click toggles, Shift+click selects the range from `selection_anchor`. Ctrl+A selects the whole roll; Shift+arrow extends from the range, plain arrow collapses. Modifier state is read from the single `AppModel.modifiers` field (see Keyboard) rather than tracked per key. **Copy/paste edits**: Ctrl+C copies the focused frame's full `ToneEdit` into `clipboard: Option<ToneEdit>`; Ctrl+V applies it to every selected frame (falling back to the focused frame), writes each via `RollManifest::set_tone`, syncs the live shader + panel when the open frame is a target, persists, and re-bakes the affected grid tiles (plus the cover if targeted). Because crop/rotation live on `EditData`, not `ToneEdit`, they are inherently excluded from paste.
- **Edit persistence**: each image's exposure and tone edits (plus crop + rotation) survive image switches, detail close, and app restarts via a per-roll manifest `.film-roll.toml` (TOML, `{ version, name?, base?, calibration_frame?, start_date?, end_date?, edits: { <name>: { exposure_ticks, contrast_lift_ticks, black_ticks, white_ticks, pivot_ticks, crop: { top, right, bottom, left }, rotation } } }`), schema **`version = 1`**. The five edit scalars are **exact `i16` fixed-point ticks**, not f32, counted in the frozen integer grid (`edit_manifest::EV_TICKS_PER_EV` = `100`, `TONE_TICKS_PER_UNIT` = `100`, `BLACK_TICKS_PER_UNIT` = `200`): exposure in EV ticks (`70` = +0.7 EV, `-300..400` = `-3..+4 EV`), Contrast in stop-lift ticks (`0` = identity, `±300` = ±3 stops, power `0.125..8.0`), Black in density ticks on its own 200-per-unit grid (`0` = identity, `±200` = ±1.0), White in density ticks (`240` = 2.4, `50..500` = `0.5..5.0`), and the Midtone pivot in window-fraction ticks (`0` = identity, `±50` = ±0.5). The **fine** grid (one tick — a Shift-held drag or Shift+key, `EDIT_NUDGE_*`) is the storage lattice itself and the coarse grid is 5 ticks, so mouse, keyboard, and disk all share one lattice; tick counts are exact and a decoded value is `ticks` divided by that control's ticks-per-unit constant, which is correctly rounded, so decoded values equal the requested ones bit for bit. Pre-release, so manifest keys were renamed outright with no migration (the five edit scalars all end in `_ticks`; old sidecars' values are simply re-edited) — and likewise the 5× tick-grid refinement silently reinterpreted current tick counts (earlier fine work reads back near identity); nothing has shipped, so no `version` bump and no migration pass. `ToneEdit`, app state, and the shader uniform stay f32; conversion happens only at the manifest boundary (`exposure_ticks`/`contrast_lift_ticks`/`black_ticks`/`white_ticks`/`pivot_ticks` and their `step_value`-based decoders in `edit_manifest.rs`). The manifest file name is deliberately function-based rather than app-based so an **app rename never orphans existing sidecars** (remember also `APP_ID = "io.github.jpttrssn.negiri"` and `CARGO_PKG_REPOSITORY` when renaming; `Config` follows `APP_ID` automatically). `RollOpened` loads the active roll's manifest once on drill-in and `reconcile()` drops entries whose file left the scan, so a recycled file name can never reattach stale edits. Writing is RAM-first: `ExposureChanged`/`DevelopChanged` mutate `roll.edits` only; flushes happen on slider drag-end (`EditSave`), on `DetailClosed`, and on window close; `save_roll_manifest` writes a temp file then renames (atomic). Reads consolidate on `ToneEdit` (a `pub` aggregate of exposure + the four develop controls, identity `Default`) via `RollManifest::tone(name)`. `decode_next()` reads the full `roll.tone(name)` (+ crop/rotation) at spawn and `convert_thumbnail` bakes it all in, so grid == detail; `EditSave` additionally re-bakes the selected tile and, in lockstep, the roll cover when the edited frame is the cover file. **Reset all edits** (`ResetAll`) restores the snapshot captured at open (`reset_tone`/`reset_crop`/`reset_rotation`), not the identity — idempotent and anchored. Storage is parameterized by directory, so multi-roll is structural; the known trade-off is that renaming/moving a file *inside* a roll orphans its edit (the name is the key); TOML keeps the file hand-editable.
- **Menus**: `header_start` renders File (Add roll, Remove roll — enabled only on the rolls view with a roll selected — divider, Export…, Quit), Edit (Select all, Copy edits — enabled while a frame context exists, Paste edits — additionally requires a non-empty clipboard), and View (About, Details…, Crop mode). Items map through `MenuAction` → `Message`; **View → About** maps to `ToggleAbout` — the About panel is a transient overlay tracked by `about_open`, never a `ContextPage`, so it covers the context slot and its X/space/navigation simply restore the current view's remembered drawer; the menu bar uses `window_id_maybe(main_window_id)` + `on_surface_action(Message::Surface)` (cosmic-files' wiring, so the popups are real Wayland surfaces rather than the in-window overlay, which per the pinned libcosmic would not paint until the next mouse move) and `item_width(menu::ItemWidth::Uniform(360))` matching cosmic-files. **View → Details…** is the single generic drawer item (gated on a detail view being open or a roll selected on the rolls view; its key_bind hint shows `Space`). Quit persists the RAM roll + config then returns `cosmic::Action::Cosmic(cosmic::app::Action::Close)` so the window close hook runs a final flush.
- **Keyboard & shortcuts**: Escape and Ctrl+F route through libcosmic's built-in `keyboard_nav` (`on_escape()`/`on_search()`); a `keyboard::listen` subscription handles the rest, all gated on `Status::Ignored` (a focused text input captures first). Bare keys: `h`/`j`/`k`/`l` mirror the arrows (`Nav`) everywhere — library selection, frame-grid highlight, detail paging (Left/Right), and crop-window moves in crop mode; Enter opens the selected cell/frame; **Space** dismisses an open About panel first (restoring the view's remembered drawer), else toggles the current view's context drawer (the editing panel / frame-info / roll-info, each *per-view remembered* via `drawer_memory` — navigation never closes a drawer (an open About does), the drawer X closes and clears its slot, stale targets clear it; text inputs swallow bare Space while typing); `?` toggles the global **help overlay** listing every shortcut in four sections (General/Navigation/Editing/Crop mode) above the toaster; selection-less presses land on the first item (`nav_target`, pure + unit-tested; nav indexes the unified `library_cells` set via `library_cell_index`, so the Add Roll tile is reachable cell 0); **scroll-into-view**: whichever grid is mounted reports its geometry via `.on_scroll(Message::GridViewport)` into the cached `grid_viewport` (cleared on roll open/back), and `Nav` reveals a selection that steps beyond the visible area — `nav_cols()` derives the column count from the viewport width (iced's `ceil((avail+spacing)/(max+spacing))`), the pure `reveal_target_y` computes the content-space target (`top < offset` → scroll up to `top`; `bottom > offset + viewport_height` → scroll down to `bottom − viewport_height`, clamped to `[0, content_height − viewport_height]`), and the handler returns `scrollable::scroll_to::<cosmic::Action<Message>>(id, AbsoluteOffset { x: None, y })`; grid ids are `rolls-grid`/`frames-grid` (`scrollable_id`, only one page mounted at a time). Before the first real scroll the viewport is estimated (offset 0, `window_height − 80` from `on_window_resize`, content from the row count); the programmatic scroll itself refires `on_scroll` and takes over precisely. `c` toggles crop mode; `e` exports; `r` rotates; `-`/`=`/`[`/`]`/`;`/`'`/`,`/`.`/`u`/`i` step Exposure/Contrast/Black/White/Pivot (the White pair is inverted like its slider: `.` brightens, `,` darkens; a bare key advances a whole number of **coarse drag steps** — `KEY_COARSE_STEPS_*`, so the keyboard and the mouse share one ladder and always land on the storage lattice: 5 × `EV_STEP` = **0.25 EV** per press for exposure, 4 × = 0.20 for the develop lifts and 0.10 for black; Shift = one stored tick, the same fine grid a Shift-held slider drag uses) — inert without a detail view, and a held editing key commits **once on release** (`editing_key_held`, mirroring the slider's drag/release cadence — no per-auto-repeat decode/TOML write). Modifiers are read from the single `AppModel.modifiers: keyboard::Modifiers` field updated by `ModifiersChanged` (this iced fork derives `KeyPressed.key` from winit's `key_without_modifiers`, so shifted symbols never arrive — modifiers are read from the event, never guessed). Escape cascade: help → crop-mode exit → `DetailClosed` (deactivate the active library search first; else close the detail view — the frame highlight and the grid's remembered drawer survive; else, on the bare grid, back out of the roll with the frame highlight dropped as part of the reset). Escape never closes the context drawer (only Space / the drawer X / navigation do). The subscription uses `Subscription::filter_map` with a **non-capturing** (zero-sized) closure, so mode flags (crop/help) are read in the message handlers, not the closure.
- **Export**: **File → Export…** / bare `e` exports the current selection (every multi-selected frame, else the focused frame; disabled/no-op without a target) into a folder chosen in the **native open-folder dialog** (`cosmic::dialog::file_chooser::open::Dialog::open_folder()`; the portal choice list has a **format dropdown** — `jpeg-90` (JPEG 90% full-res, 300 dpi), `jpeg-82` (JPEG 82% at 2048, 72 dpi), `png-16` (16-bit PNG full-res, 300 dpi), resolved by the pure `options_for_choice` — and an **overwrite checkbox**, default off). `begin_export` snapshots edits from the **in-memory** roll (so exports always match the screen, even for an un-flushed edit), then `export_frames` runs sequentially on the blocking pool; overwrite-off skips any existing `<name>.<ext>` **before decoding**. **Naming**: undated rolls keep `<stem>.<ext>`; dated rolls export as `YYYYMMDD-<roll-hash>-<frame>.<ext>` — start date + a deterministic FNV-1a 6-hex `roll_hash(dir)` (masked to 24 bits, deliberately NOT std's `DefaultHasher`, which is unstable across Rust versions) + 1-based zero-padded full-roll position, produced by the pure `dated_export_name(format, start_iso, index, roll_hash)` (returns `None` for a malformed start date, falling back to the plain name) — so a plain filename sort groups a same-day multi-roll folder by roll. **EXIF stamping** (dated rolls): `DateTimeOriginal` = start date at 00:00:00 + the frame's full-roll position in seconds (synthetic film-capture time), `DateTimeDigitized` = the RAW's own scan time when present (read as its raw EXIF text via `exif_writer::raw_datetime_original` — NOT `load_frame_meta`'s display value, which kamadak normalizes to hyphen form; the writer enforces the exact `YYYY:MM:DD HH:MM:SS` colon shape), via the hand-rolled TIFF blob spliced as JPEG APP1 (`jpeg_app1`/`splice_after_soi`) or PNG `eXIf`. Encoders are luminance-only (negatives are monochrome today): Luma JPEG (`jpeg-encoder`) and 16-bit grayscale PNG via the `png` crate directly (big-endian samples, `set_pixel_dims` adds `pHYs`), with density tags (JFIF dpi / `pHYs` px-per-meter) and a `sRGB` chunk on the PNG; geometry is `crop_rgba` then `rotate_quarters` (`bake_geometry`/`bake_geometry16`). Every file is written atomically: encode to `<name>.<ext>.tmp` then rename over the target. A small 18 px **determinate circular ring** in `header_end` shows progress while a batch runs (`ExportProgress { done, total }` streamed over a channel; zero space when idle); File→Export/`e` refuse to stack a second batch; completion toasts report done / skipped (overwrite-off) / failed, with the `(dated {date})` variant for dated rolls. The roll scan skips `.jpg`/`.jpeg`/`.png` files (`is_export_artifact`), so exporting into a roll's own folder never shows the outputs back up as fake frames or the cover. When color negatives eventually land, the encoders must restore the RGB/RGBA interleave (see the note in `export` — `png::ColorType::Rgb16`, `ColorType::Rgb` for JPEG).

- Decode chain: `decode_next()` fills up to `MAX_CONCURRENT_THUMBS` slots with distinct `Loading` tiles → one `tokio::task::spawn_blocking` per file (`decode_thumbnail`, reading tone/crop/rotation from the active roll at spawn), returned as a `Task::batch`. `thumb_inflight` enforces the cap and de-duplicates: a name already running is never spawned again (a mid-chain re-bake waits instead of racing), and the EV + tone curve are read at spawn time — startup tiles bake stored edits, re-baked tiles the freshest. `ThumbReady` removes the finished name and pumps; `RollOpened` clears the set, the final `DetailClosed` roll-exit drops it, `RollsLoaded` clears it alongside a new round. Roll covers are pumped by the sibling `decode_covers()` — same cap/discipline, keyed by dir.
- Detail pump: `decode_detail_next()` spawns only when no decode is in flight and something is selected. **Progressive two-level loading through the single slot**: with no shader yet it decodes the 2048 overview; once `detail_zoom` reaches the **adaptive trigger** `native_level_up_zoom()` — the earlier of the current texture's 1:1 cap (`min(max_detail_zoom(), NATIVE_ZOOM_THRESHOLD)`; see the level-up-reachability bug fix in the Detail view bullet) — a wheel fires a native-cap re-decode (`MAX_TEXTURE_EDGE` = 8192) whose arrival swaps the texture in place — `fresh_open` (shader absent) gates the thumbnail fade so a level-up never re-flashes the thumb, and the swap re-applies zoom/pan + tone curve. `detail_native_queued` makes the level-up one-shot, and it's set early when the sensor's true long edge (`src_long_edge`, threaded out of `decode_raw_detail`) never exceeded `HI_RES_SIZE` — that *source* edge, NOT the capped overview width, decides native-ness (a large sensor downscaled to just under 2048 was the original false-positive). A superseded decode's arrival frees the slot via the stale guard and re-pumps; the wheel trigger is additionally gated on `detail_inflight.is_none()`, so wheels that keep zooming through a running decode (up to the projected native cap) never re-enter the busy slot — the landing re-check (`handle_detail_ready` re-checks the trigger after freeing the slot, `Ok` landings only) covers a zoom taken mid-load. Failures do NOT auto-retry (re-select retries; after an `Err` the zoom trigger stays live so the next wheel retries). When an overview is requested, `decode_detail_next` first consults `detail_cache` — a hit builds the shader from cached mono with no decode/fade; misses decode and insert on landing. `open_frame` also calls `preload_detail_neighbors` (fills the LRU `DETAIL_PRELOAD_DISTANCE` frames either side, honoring `MAX_CONCURRENT_PRELOADS`, skipping cached/in-flight). Edits are applied in-shader at open time, so a cached mono stays valid across edit changes.
- Thumbnail pipeline: `convert_thumbnail` is the single CPU body — `downsample_thumbnail` → `bake_develop` → u8 quantize → `orient` → `scale_crop`/`crop_rgba` → `rotate_quarters` → `Handle::from_rgba` (see the Thumbnail pipeline bullet for the per-step detail). Grid == export == detail hold structurally because this one body, plus the `develop_matches_wgsl_transcription` parity test against the shader, is where the non-shader tone math lives.
- Detail pipeline (`decode_raw_detail`): `rawloader::decode_file` → `normalize_samples` → `crop_samples` (masked borders) → `src_long_edge` → bayer `flatten_bayer` (per-class bases via `class_gains`, then 2×2 CFA cell averaging) or cpp≥3 `luma` → `resize_area` downscale to `max_edge`, returning `DetailDecode { mono, width, height, src_long_edge }`. The mono is **true sensor-linear** and stays that way — there is no CPU inversion field; the GPU shader does the whole develop per fragment. `src_long_edge` (post-crop, pre-downscale) decides whether the overview was already native. The downscale cap is a parameter: `HI_RES_SIZE` at overview level, `MAX_TEXTURE_EDGE` at level-up; `resize_area` treats a cap ≥ both source edges as identity, so ≤8K/small sensors decode at full resolution.
- **GPU pipeline** (`Pipeline::new` in `src/shader.rs`): one-time `ShaderModule` from `include_str!("shader/exposure.wgsl")`, `BindGroupLayout` (texture, sampler, uniform buffer), `PipelineLayoutDescriptor`, `RenderPipeline` (fullscreen triangle, target `Bgra8Unorm` to match iced's framebuffer), `Buffer` for `Uniforms`, `Sampler` (linear + ClampToEdge). Texture + bind group are created lazily in `Primitive::prepare` on the first frame (they need the mono data); later frames only update the uniform buffer via `queue.write_buffer`. The WGSL `fs_main` already applies `linear_to_srgb` per fragment, so the target is `Unorm` (linear) — `UnormSrgb` would double-encode; if libcosmic ever switches to an sRGB-aware framebuffer, drop/no-op `linear_to_srgb` and swap back to `Bgra8UnormSrgb`. Texture re-upload is keyed by `image_id: u64` (`AppModel.next_image_id`, `wrapping_add(1)`) remembered in `DetailPipeline::current_image_id` — without it iced reuses the same pipeline across selections and the old mono stays bound ("second image still shows first").
- WGSL uses the canonical 3-vertex fullscreen triangle (`-1,-1 / -1,3 / 3,-1`) with NDC passed through directly. The earlier `(vec2(1u, 2u) + vi) % vec2(6u) < vec2(3u)` pattern produced only the upper-right half of the viewport, because under wgpu the render-pass scissor clips to the viewport rect rather than the original primitive bounds.
- Detail view layout: the shader widget is `Length::Fill × Length::Fill` directly inside a Fill × Fill `widget::container` — no wrapping Grid. Because `widget::Shader` has no `.content_fit()`, the WGSL does the `ContentFit::Contain` math itself. Letterbox/pillarbox bars are alpha-blended (`vec4(0,0,0,0)` + `BlendState::ALPHA_BLENDING`) so the COSMIC panel background shows through rather than solid black frames (the earlier `Grid::with_capacity(...)` approach failed because the Grid reports widget bounds `(available_width, available_width)` and `Primitive::render` uses `instance.bounds ∩ physical_bounds` for `set_viewport`, so the shader painted into the header). `detail_view()` is pushed onto a `Stack` OVER the always-mounted grid (blocking `MouseArea` in between; the preview `DetailArea` is nested inside so its `capture_event()` wins over the preview).
- **Per-frame uniform** (`Uniforms`, all f32): `exposure` (the linear sensor *gain* — `2^-EV` on the film path, so +EV brightens the positive; never the raw EV), `tex_w, tex_h` (texture dims for the contained math), the physical-pixel scissor rect `sc_x, sc_y, sc_w, sc_h`, `zoom` (log2, 1 = contain), `pan_x, pan_y` (image-center displacement, physical px — `prepare()` multiplies logical by `viewport.scale_factor()`), the crop box `crop_l, crop_t, crop_w, crop_h` (source-px margins scaled onto the texture by the Rust-side `crop_uv_geometry`), `rot` (quarter-turns), `show_mask` + `pad` (crop-mode dim overlay + the `CROP_MODE_PADDING = 100.0` margin that keeps a white surround even at exact aspect), and the develop block `dev_base, dev_black, dev_white, dev_contrast, dev_pivot` mirroring `film::Develop`. Three bindings only (texture, sampler, uniform) — there is no curve texture. `view_uv` contain-fits the CROPPED frame *as displayed* (`rotated_dims(crop_w, crop_h, rot)`, less `pad` per side) and scales by `2^(zoom−1)` about the image center, displaced by pan; fragments outside output alpha 0 (same blend trick as the bars).
- Constants: `THUMB_SIZE = 384.0` (decode cap + grid cell), `HI_RES_SIZE = 2048` (detail overview cap), `FADE_SPEED = 5.0` (thumb-fade-out/sec), `TILE_ASPECT = 1.0`, `BASE_SAMPLE_TARGET = 250_000`, `MAX_CONCURRENT_THUMBS = 4` (a one-line knob, see the CPU-thumbnails decision), `DETAIL_CACHE_CAPACITY = 40` (LRU frames), `MAX_CONCURRENT_PRELOADS = 2`, `DETAIL_PRELOAD_DISTANCE = 1`, `MAX_DETAIL_ZOOM = 7.0` (≈64× contain ceiling on the dynamic 1:1 cap), `NATIVE_ZOOM_THRESHOLD = 2.0` (prefetch level-up trigger in log2, when the 1:1 cap sits above it; the actual trigger `native_level_up_zoom()` is `min(cap, this)` so it's reachable on every layout), `MAX_TEXTURE_EDGE = 8192` (native cap), `CROP_STEP_PX = 5`, `CROP_NUDGE_PX = 1`, `CROP_RESIZE_STEP_PX = 10`, `MIN_CROP_WINDOW = 4`, `CROP_MODE_PADDING = 100.0`, `SEARCH_DEBOUNCE_MS = 300`, `film::MIN_TRANSMISSION_DEV = 1e-6`, `film::DEFAULT_FILM_BASE = 0.8`, `film::DEFAULT_D_MAX = 2.4`, `film::MIN_PLAUSIBLE_BASE = 0.1`.

## Decisions

ADR-style records (Y-statement form: context → choice → accepted tradeoff). Status **Accepted** unless marked **Superseded**.

- **CPU thumbnails, not GPU** — In the context of edit-aware tiles, we chose CPU re-decodes (rawloader is CPU-only; GPU samplers can't area-average; a GPU tail at ≤384 px buys nothing) over per-tile shader objects, accepting one RAW re-decode per edited file on edit release. (Est. as a limitation, then ratified.) — **Accepted**
- **Half-float `R16Float` texture** — In the context of wgpu 28 not filtering `R32Float`, we store the linear mono as f16 (f32→half in `prepare`), accepting a small quantization on upload. — **Accepted**
- **`2^-EV` sensor-gain flip** — In the context of the film path's clear-film inversion, the EV gain is flipped in sign at the point EV meets the sensor data (`2^-EV` then density inversion) so +EV always brightens the positive; `Uniforms.exposure` carries the *gain*, never the raw EV. — **Accepted**
- **Commit-on-release edit cadence** — In the context of per-keystroke RAW re-decode/TOML churn, edits stream live to the RAM + shader and commit exactly once on release/flush (`commit_edit()`), accepting a beat of grid lag behind the detail view. — **Accepted**
- **Detail-overview LRU** — In the context of instant return to recently-viewed frames, we deliberately retain `DETAIL_CACHE_CAPACITY = 40` overviews (~500–670 MB peak) across close/roll switches, accepting a bounded memory cost; native level-up buffers and thumbnail caches are never retained. — **Accepted**
- **Crop mode as a VIM-like modal state** — In the context of the old dimmed-crop overlay toggle, cropping is a real keyboard mode (`c` toggles; white surround + dim mask; Esc exits mode first; crop keys are the only active edits), accepting extra key depth for a cleaner inspect-workspace. — **Accepted** (the "View dimmed crop area" toggle it replaced: **Superseded**)
- **Search is library-only** — In the context of a search that once filtered open-roll frame names, frames are never filtered (the grid always shows every file), accepting that frame lookup stays name-sorted paging. — **Accepted**
- **Flatten-before-average base measurement** — In the context of thumbnail speed, per-class bases are measured at thumbnail scale after the downscale, accepting subtle high-contrast differences vs. the detail render. — **Accepted**
- **Remove roll is non-destructive** — In the context of library management, removing a roll edits config only (files + sidecar untouched), accepting that "delete" still requires manual file removal. — **Accepted**

## Known limitations & next steps

1. **Tone editing is manual, not per-stock**: the drawer is a *persisted* manual develop (exposure, contrast, black, white, pivot) rather than stock-tuned curves, so there is no equivalent of picking a known emulsion's curve. Cast WB stays self-calibrated per image from clear-film plateaus, so margin-less frames rely on the `MIN_PLAUSIBLE_BASE` fallback. **Calibrate-from-a-frame is implemented**: one designated calibration frame per roll supplies the clear-film base — set via **Edit → Calibrate from this frame**, marked by a tile dot, and its measured plateau (`measure_base`) becomes the roll's `base` — so the remaining natural next steps are AsShot-WB priors for margin-less frames and color stocks using `invert_mono`/`measure_base_channels`.
2. **No live refresh**: re-adding a roll re-scans it (the Add Roll tile doubles as a manual refresh), but an open roll's frame list is fixed for the session and the library list has no global rescan button.
3. **Memory unbounded** across many decoded thumbs (no LRU/eviction); ~600 KB each. Detail view holds one oriented mono `Vec<f32>` (~16 MB at 2048×2048 f32) + its GPU texture; zooming past the threshold re-decodes it at native cap (`MAX_TEXTURE_EDGE`), so a >8K sensor transiently holds up to a `long_edge ≤ 8192` mono buffer (~0.5 GB worst case at 8192² f32) until the old buffer is dropped on swap. Live buffers are dropped on close/reselect, but the **detail-overview LRU** (`DETAIL_CACHE_CAPACITY` = 40 × ~12–17 MB ≈ 500–670 MB peak) deliberately retains recently-viewed overviews across close/roll switches — a bounded, intended tradeoff for instant return; native level-up buffers and the thumbnail no-cache policy are unchanged.
4. Decode errors are **logged**, no longer silent (plain `eprintln!` messages matching the codebase's prefix-less "failed to …" style, e.g. `failed to decode <path>: <reason>`, `detail decode failed for <name>: <reason>`): `decode_raw` (thumbnail/cover) and `decode_raw_detail` (detail/export) now thread rawloader's actual error string out of the spawn_blocking call (`Result<DetailDecode, String>`; the two sample-count guard failures carry a message too), `handle_detail_ready` logs the detail failure **once per selection** (`detail_logged_failure`, so wheel-driven re-decodes of the same doomed frame log once, not per notch), preload failures stay quiet (speculative), and `export_one` logs + maps to `()` for its `Result<(), ()>` signature. Non-RAW files are still listed and show the missing icon, and a failed hi-res detail decode still keeps the thumbnail — selecting another file and back retries on demand.
5. **Grain/noise/sharpness**: area-average downscale, luminance collapse, full-res bayer flattening, gentle unsharp mask — plus the post-decode bandwidth savings on the GPU side (one linear texture upload vs. a continuously-re-encoded sRGB image). Remaining stackable option — a denoise pass for very underexposed captures. Capture-side: scans exposed with clear film far left in the histogram waste SNR; exposing so the base sits near saturation (~85–95%) keeps several more stops of detail in dense areas.
6. **Exposure EV precision** — **resolved**: the manifest no longer stores `f32`. All five edit scalars are exact `i16` fixed-point ticks against the frozen integer grids (`edit_manifest::EV_TICKS_PER_EV` = `100`, `TONE_TICKS_PER_UNIT` = `100`, `BLACK_TICKS_PER_UNIT` = `200`): exposure `-300..400` ticks (`-3..+4 EV`, default `70` = `+0.7 EV`), Contrast lift `±300` (`0` = identity, `±3` stops), Black `±200` (identity `0`), White `50..500` (`240` = 2.4), Midtone pivot `±50` (identity `0`). Both slider rungs are whole-tick counts (`FINE_TICKS` = 1, `COARSE_TICKS` = 5) and the bare keys are whole multiples of the coarse rung (`KEY_COARSE_STEPS_*`), so slider, keyboard, and storage share one lattice; the slider's range is derived from those same bounds. The runtime `Uniforms.exposure` remains `f32` (one value per frame, negligible) — no need for an f16 uniform.
7. **GPU vs CPU for thumbnails (decided: CPU)** — evaluated when wiring edit-aware tiles. GPU does NOT help thumbnail *loading*: `rawloader::decode_file` is the dominant cost and is CPU-only; the quality-relevant steps (full-res `flatten_bayer`, linear-light area-average downscale) are intentionally CPU-side because a GPU sampler can't do area-average (mip/bilinear differs), and uploading full-res mono per tile would be ~100 MB/tile. The GPU-able tail (EV multiply + sRGB + quantize at ≤384 px) is trivial CPU, so per-tile shader objects buy nothing. GPU stays where it already pays: the single live detail shader. Consequence taken instead: thumbnails are *re-decoded* CPU-side with the EV baked in on edit release — one RAW re-decode per edited file, background + bounded-concurrent, so the grid updates a beat after the detail view. If instantaneous grid feedback were ever required, the alternative is caching the un-exposed linear mono per tile (~590 KB @ 384 px f32) and re-encoding on edit — rejected now because it breaks the memory-boundedness that the concurrency cap/no-cache currently guarantees (see #3). The accepted flatten-before-average tone swap (per-class bases measured at thumbnail scale after averaging) plus the ≤4-way decode concurrency (transient RAM peak ≈ `MAX_CONCURRENT_THUMBS` decoded full-res buffers) are the current price of the speedup; `MAX_CONCURRENT_THUMBS` is a one-line knob.
